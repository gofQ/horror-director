## Invariants to keep
- Simulator, pacing and comparison never write to project data, autosave, library storage, undo history or exports (covered by store tests).
- Pinned Route A is a copy of choices bound to a project id; it is never pruned silently — invalidation (graph edits, lowered step cap) is shown as an
  explicit warning and marks the comparison incomplete. All simulator state resets on active-project change.
- Shots are planning notes only: independent of triggers/transitions, authored timing is never changed implicitly (warnings only); reordering changes sequence, not timing.
- Stored records are `{ v: 8, project }`; `v: 1`–`v: 7` records stay readable; old records/legacy key are normalized in memory only and never rewritten at boot. Do not write older record versions again.
- Transition direction is planning data only (never evaluated); shot links must belong to the transition's source/target scene (validated on import; store refuses invalid links; `deleteShot` refuses while linked unless `clearReferences`, which removes shot and links in one undo step). `updateTransition` cannot change endpoints.
- Audio cues are planning notes only: never played or evaluated, independent of triggers/ambience/shot sound notes/transition audio continuity, excluded from pacing and simulation. Overlaps are normal layers (display lanes are derived, never stored); silence mutes nothing; authored order and timing are never changed implicitly (warnings only).
- The Sequence overview is a derived view: no persisted fields, no store writes, no history entries, no storage writes (covered by an E2E storage-snapshot test); selection is derived from the current scene each render, so deleted items/scene or project switches cannot leave a stale selection; authored timing is never clamped (axis extends instead).
- Branch conditions are never evaluated; IF nodes take zero scene time and add no visit/trigger; comments never affect simulation, reachability or statistics; `deleteScenes` removes a node with all its connections in one undo step without touching other scenes' data; custom scene types never change a scene's canonical `kind` semantics (base kind locked while in use, deletion detaches explicitly); `updateTransition` cannot change endpoints/pins.
- Flag state exists only inside `simulateRoute` results (never in project JSON, storage or history); free-text conditions are never parsed; only `expression` is evaluated and only by the simulator. Flags are referenced by id; `deleteFlag` never leaves dangling references (`detach` clears them in the same undo step). Set Flag/IF nodes take zero scene time and add no visit/trigger.
- Reroute points never influence simulation, analysis, reachability, pacing, comparison or connection rules; they are cleared only by explicit user actions (point removal, Clear, Auto Arrange — all undoable). Pasting never creates dangling references, duplicate ids or invalid pins; an inconsistent stored record is never opened, repaired, overwritten or deleted without an explicit user action (Open anyway saves a raw copy first).
- Event, Delay and Random nodes take no scene time and create no scene visit or trigger occurrence; Events are never merged with scene triggers/audio cues and never reach pacing. A Delay's seconds are added to the route clock exactly once and only between scene visits (scene and link durations are untouched). Random outcomes are always an explicit user choice (hand-picked what-if, or an explicitly committed seeded roll); `simulateRoute` never draws randomness, the seed/roll preview/provenance live only in `useSim` and are never persisted, exported or put in history; a committed choice is never rerolled.
- A Sequence never runs its stages as alternatives or in parallel, never offers Completed before both Returns, never skips an unfinished stage and never creates a scene visit or trigger occurrence; Sequence/Return take zero time (Delay seconds in a stage are counted exactly once through the same `pathDur` as everywhere else). Authoring states reachable through the UI (disconnecting a link, deleting a stage node or a Sequence, partial paste) must stay *warnings* so stored records never become integrity errors; only structurally impossible data (wrong owner/stage, forbidden stage content, shortcuts) is an error.
- Library metadata never enters project JSON; the legacy storage key is never modified or deleted.
- Intensity is authored design intent: no fear score, no tension curve, no "best route" ranking anywhere.

## Known limitations and remaining risks
- Simulation is manual and assumes the full duration of every scene; free-text conditions are never evaluated (only structured flag conditions are, and only in the simulator); per-project routes are not remembered.
- Pacing thresholds are untuned heuristics (only repeated-type window and trigger-free minimum adjustable); hypothetical events are included in counts (flagged).
- Comparison supports exactly one pinned route against the live route (no multi-route matrix); time shifts of shared events are shown, not explained.
- The aligned comparison timeline hides nothing but gets dense for very long routes (no zoom); scene bands are not drawn in it.
- Shots: simple list only (no storyboard images, camera timeline editor or Unreal import). The list shows authored (array) order; "out of time order" is a warning and "Sort by time" an explicit action. Duplicate/new shots start where the previous one ends.
- Sequence view: authored planning timing only (no simulation of runtime conditions); "conditional" means a non-empty free-text condition; dense scenes rely on zoom + horizontal scroll (no zoom-to-selection, no drag editing); track labels are truncated; selection/zoom/cursor/mode are session-only.
- Audio planner: no playback/waveform/spatial rendering, no asset browser or generation; the timeline axis stretches to include cues that overrun the scene; the planner is a list plus timeline (no drag-to-resize). Cue lanes are derived for display only.
- Stored records are schema- and integrity-validated on load (v0.7C); the checks are exactly the blocking import rules of `validateProject`, nothing more (e.g. warnings never block, nor does a missing character *definition* without a reference).
- Productivity: copy/paste is per project and session-only (no cross-project paste, no system clipboard); Auto Arrange discards reroute points (undoable); a drag of many nodes translates points only for links whose two ends move together; box selection and the Select/Pan toggle use React Flow's selection (Partial mode); with more than 60 nodes only visible elements are rendered (E2E for big graphs counts rendered nodes accordingly); the integrity check applies the import validation rules, so a hand-edited or buggy record that parses but is inconsistent needs *Open anyway* (the project then opens as-is, problems included); keyboard shortcuts act when focus is on the canvas or on nothing; touch alternatives are the Select/Pan toggle, the batch panel and the Inspector's reroute buttons (long-press on the canvas still opens the menus; not exercised on a real touch device).
- Narrative state: Boolean flags only (no numeric/string variables, no scripting); a structured IF needs flags to exist (the builder is disabled otherwise); a Set Flag node needs a click-through like any link (every link is an explicit choice); the State inspector does not diff against a pinned Route A; an override only compares the structured result at the IF, it does not detect that a later flag change makes an earlier choice inconsistent; flag-name uniqueness is case-insensitive on trimmed names only (no Unicode normalization); the Flag manager is in the project inspector, which is only visible when nothing is selected (on mobile close the selection first).
- Graph editor: no separate AND/OR/NOT nodes, parallel/nested/multi-output Sequence or cross-project paste (later candidates); an IF node has exactly one input pin and one connection per output; the step cap counts links (an IF hop costs two); the simulator does not look ahead through an IF node when marking options blocked by loop limits (blocking is shown on the branch outputs); links touching an IF node cannot carry a transition design (Insert IF is refused for designed transitions); long-press is the touch alternative to right-click (not exercised on a real touch device); the minimap draws nodes from measured sizes kept in component state (they were never written back before, so the minimap used to be empty).
- Flow control: Event/Delay/Random nodes are planning markers (nothing executes in a game); a Delay is extra time between scene visits only (scenes still consume their full authored duration, no in-scene delay editor); Random probabilities are authored intent that a single route cannot verify, a roll is previewed and must be committed, and its seed/provenance are session-only (a pinned Route A keeps its marks only for the session; routes loaded without marks show `source unknown`); provenance is keyed by the choice index, so after graph edits that shorten the route it is truncated with the route; the roll's decision context is (seed, node id, choice index); the Flow trace is a list, not a chart, and the chart still shows scene triggers only; Event/Delay/Random links cannot carry a transition design; Auto Arrange places the new nodes with the same layered layout as other logic nodes.
- Sequence: exactly two stages; no nesting, no parallel execution, no loops inside a stage (a stage is a straight Event/Delay/Set Flag chain); a stage node cannot be shared; Completed may lead anywhere normal (including into another Sequence — chaining is allowed, nesting is not); the closed-loop analysis still counts a stage entry as a way out of a scene loop; a Return's owner/stage cannot be edited while it is connected (disconnect first); the Flow trace is a list and the chart still shows scene triggers only; the frame is rebuilt by replaying the route on every change (cheap, bounded by the step cap).
- Hand-off: readiness reflects authored data only (a cue without an asset reference blocks its audio chain by design; confirmable proposals never block); briefs/prompts are guidance, not engine code, and Horror Director cannot see which assets or systems exist in the target project; the explorer keeps selection/filters only for the session; v0.8A task ids changed once; there is no per-task progress tracking.
- Production planner: plans are guidance only (no engine code, no importer, no runtime integration, names are proposals); the preview renders the Markdown subset the planner emits (not a general Markdown renderer); the engine choice is session-only; the plan text is localized but project content is not; stage nodes inside a Sequence appear in the Sequence task and the Event/Delay tables, not as separate tasks; every Delay is reported as inter-scene time.
- Showcase: the guide's dismissal is per browser; the legacy sample still seeds a fresh library; a fresh first-run library therefore does not show the guide until the showcase is added.
- Context menu: Paste needs `navigator.clipboard.readText` (unavailable or denied ⇒ disabled/explained, Ctrl/Cmd+V works); `contenteditable` regions and `select` popups are not text-menu targets (`select` gets the application menu); long-press is not exercised on a real touch device; the keyboard path anchors to the focused element.
- Downgrade: a build older than v0.7E shows `v: 9` records as damaged (builds older than v0.7D also `v: 8`, older than v0.7C also `v: 7`; data preserved, never overwritten); exported schema-2 files cannot be imported by older builds ("newer schema").
- A schema-level error (e.g. invalid shot value) stops validation before integrity checks, so duplicate-id errors only appear once schema errors are fixed.
- Multiple browser tabs are not merged (detection and blocking only); localStorage quota is shared by all projects and backups.
- Undo history is session-only and cleared on project switch; deleted projects have no trash.
- E2E covers Chromium only (mobile is checked via a 390 px viewport test and manually); no visual-regression tests.
- Production bundle is ~540 kB (no code-splitting). Turkish copy has not had a native game-industry review.
